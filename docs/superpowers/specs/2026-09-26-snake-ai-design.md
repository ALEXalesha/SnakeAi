# Нейро-змейка - спецификация

Дата: 2026-09-26
Статус: утверждено (часть 1 - Алексеем по шагам брейнсторма; части 2-4 - по его «начинай
работу полностью без остановок»)

## 1. Что это

Змейка на двоих на поле 32x32: Алексей играет стрелками, против него - змейка-нейросеть.
Главное отличие от обычной змейки: **в игре нет кода правил**. Каждый ход клавиша игрока и
ход соперника подаются в сеть-мир, и сеть сама выдаёт новое поле: куда сдвинулись змейки,
кто съел еду, кто врезался и где появится новая еда. Игра только рисует то, что выдала сеть,
считает очки и читает клавиши.

Правила живут в «учителе» - обычном коде на ~100 строк, - но он нужен только при обучении:
по нему генерируются примеры и проверяется точность. В собранную игру учитель не входит.

## 2. Стек

Python 3.13, numpy, PySide6 (Qt 6). Сети свои - слои, обратное распространение и Adam на numpy,
без PyTorch. Звуки синтезируются numpy и играются через QtMultimedia. Окно - Qt, а не pygame: Алексей
выбрал 26.09 настоящее окно Windows с обычными кнопками, ползунками и графиками. pytest для тестов, PyInstaller + NSIS для сборки,
как у AiCar.

## 3. Устройство (часть 1)

| Папка / файл | Что делает |
|---|---|
| `nn/` | свои слои: свёртка 3x3 и 1x1, ReLU, глобальный максимум, плотный слой, Adam, сохранение в `.npz` |
| `world/` | кодировка поля, сеть-мир, шаг мира сетью (`WorldNet.step`) |
| `teacher/` | правила кодом и генерация примеров; только для обучения и тестов |
| `player/` | вход соперника (окно вокруг головы), сеть соперника, бот для подражания |
| `train/` | обучение сети-мира и соперника, запись моделей и кривых обучения в `models/` |
| `game/` | окно на Qt: меню, матч, статистика, настройки, звуки |
| `models/` | обученные веса и их паспорта (точность, кривые обучения) - часть репозитория |
| `tests/` | pytest |

Ход игры:

```
клавиша Алексея + ход сети-соперника
        -> сеть-мир (старое поле + два хода)
        -> новое поле + события «съел» / «врезался» + карта, где родится еда
        -> если кто-то съел: клетка новой еды выбирается из карты сети
        -> если кто-то врезался: раунд окончен
```

Состояние игры между ходами - только поле, которое выдала сеть. Стартовая расстановка
раунда (две змейки длины 3 и еда в центре) - картинка-данные, не правило.

## 4. Кодировка поля

Каждая клетка - один из 12 классов:

| Класс | Смысл |
|---|---|
| 0 | пусто |
| 1 | еда |
| 2 | голова змейки 1 (Алексей) |
| 3-6 | тело змейки 1, указатель на соседа ближе к голове: вверх, вниз, влево, вправо |
| 7 | голова змейки 2 (сеть) |
| 8-11 | тело змейки 2, указатель так же |

Почему указатели, а не «срок жизни» клетки: срок жизни - целое до ~1000, и сеть пришлось бы
учить точной арифметике. С указателями все правила локальны: хвост - это клетка тела, на
которую не указывает ни один сосед; шея - клетка тела, указывающая на голову; направление
змейки - указатель шеи. Длина змейки для правил не нужна вовсе, поэтому сеть, обученная на
коротких змейках, так же ведёт длинные.

Ход каждой змейки - одно из 5 значений: вверх, вниз, влево, вправо, «нет нажатия».

## 5. Правила (учитель)

За ход, для каждой змейки:

1. Направление = нажатое; «нет нажатия» или разворот назад - прежнее направление.
2. Цель = голова + направление.
3. Врезалась, если цель за краем поля, цель занята любой змейкой (голова или тело, хвост
   тоже - он ещё на месте), или обе змейки идут в одну клетку (тогда врезались обе).
4. Если кто-то врезался - раунд окончен, поле дальше не нужно.
5. Иначе: цель становится головой; старая голова - телом с указателем на цель; если в цели
   была еда - змейка съела и хвост остаётся (змейка выросла), иначе хвост исчезает.
6. Если кто-то съел - новая еда в случайной пустой клетке нового поля.

## 6. Сеть-мир (часть 2)

Вход - плоскости 32x32 (или любого размера, сеть к размеру не привязана):
12 плоскостей класса клетки, 5 + 5 плоскостей хода змеек (одинаковые по всему полю),
1 плоскость «внутри поля» (за краем свёртка видит нули - так сеть знает, где стена).
Итого 23 канала.

```
23 -> свёртка 3x3, 48 -> ReLU -> свёртка 3x3, 48 -> ReLU -> свёртка 3x3, 48 -> ReLU  (местная часть)
      глобальный максимум по полю (48) -> плотный 48->32 -> ReLU
          -> плотный 32->4: события «змейка 1 съела», «змейка 2 съела», «1 врезалась», «2 врезалась»
          -> плотный 32->48: добавка ко всем клеткам (так хвост узнаёт, что его змейка съела)
      свёртка 1x1, 48 -> ReLU -> свёртка 1x1 -> 13: 12 классов клетки + 1 оценка «здесь родится еда»
```

Поле зрения местной части - 7x7: этого хватает на все местные правила (две головы, идущие в
одну клетку, стоят через клетку). Единственное дальнее правило - хвост не исчезает, если
змейка съела, - идёт через глобальный максимум: клетка с «съедаю» есть одна на поле, максимум
её находит и передаёт всем клеткам.

Потери:

- классы клетки - перекрёстная энтропия по клеткам, с весом 20 у клеток, которые меняются,
  и у их соседей (иначе 99% пустых клеток задавят редкие правила); на ходах, где кто-то
  врезался, поле не учится (оно не нужно);
- события - двоичная перекрёстная энтропия;
- новая еда - softmax по всем клеткам поля, цель - клетка, которую выбрал учитель; учится
  только на ходах со съеданием. Так сеть сама выучивает «равномерно по пустым клеткам».

Обучение на маленьких полях (8-16 клеток) - правила от размера не зависят, а свёртки на
маленьком поле в разы быстрее; в конце дообучение на полях 32x32.

Данные - партии учителя: боты с разной долей случайных ходов (чтобы были и длинные змейки,
и столкновения всех видов), плюс поля со змейками, выращенными случайным блужданием, - чтобы
встречались расположения, до которых бот сам не доводит.

Цель точности на отложенных примерах 32x32: поле совпало с учителем целиком - не меньше
99.5% ходов; события - не меньше 99.9%; вероятность еды на занятых клетках - в сумме меньше
1%. Точность пишется в паспорт модели и показывается в статистике.

## 7. Соперник (часть 2)

Вход - окно 15x15 вокруг своей головы в 4 плоскостях (препятствие - тело, голова или край
поля; еда; голова другой змейки; своя шея), плюс направление на еду (dx, dy / 32) и своё
направление (4). Выход - 4 направления (абсолютные). Сеть - плотная: 906 -> 128 -> 64 -> 4.

Бот для подражания: кратчайший путь до еды поиском в ширину в обход препятствий; если пути
нет или шаг ведёт в тупик - ход в соседнюю клетку с наибольшей свободной областью (заливка).

Обучение:

1. Подражание: партии бот против бота (и против случайного), сеть учится повторять ход бота.
2. Пробы и ошибки (REINFORCE с базой): игра против бота в учителе, награда +1 за еду,
   -1 за столкновение, +1 за победу в раунде. Новая версия принимается, только если на
   проверочных партиях против бота выигрывает не хуже подражательной.

Три версии на выбор в настройках: «новичок» (ранний снимок подражания), «средний»
(подражание), «сильный» (после проб и ошибок).

## 8. Игра (часть 3)

Окно 1040x720: поле 32x32 по 20 пикселей слева, панель справа. Окно открывается там, где
его закрыли (то же правило, что в AiCar и калькуляторах: если того монитора нет - место
выбирает Windows).

Экраны:

- **Меню**: Играть, Статистика, Настройки, Выход.
- **Матч**: отсчёт 3-2-1 со звуком, раунд до столкновения, выжившая змейка получает очко,
  обе врезались - ничья без очка; матч до 3 очков. Панель: счёт, длины змеек, уверенность
  сети-мира (вероятность самого вероятного класса в самой неуверенной клетке), подсказка
  клавиш. Esc - пауза, из паузы - в меню. По желанию поверх поля - карта «где родится еда».
- **Статистика**: матчи и раунды, победы и поражения по уровням соперника, самая длинная
  змейка, съедено еды; точность сети-мира из паспорта; графики обучения обеих сетей.
- **Настройки**: скорость (мс на ход), соперник (новичок / средний / сильный), громкость,
  цвета (3 палитры), показывать карту еды.

Клавиши: стрелки и WASD; нажатия копятся в очереди до 2, чтобы быстрый двойной поворот не
терялся.

Звуки (синтез): еда, столкновение, отсчёт, победа, поражение.

Данные: `%LOCALAPPDATA%\SnakeAIGame` - `settings.json`, `stats.json`, `window.json`; рядом с
exe лежит `portable.txt` - тогда в папке `saves` рядом (как в AiCar). Битый файл не роняет
игру - берутся значения по умолчанию.

## 9. Проверки (часть 4)

- `nn`: градиенты каждого слоя сверяются с численными; сохранение и загрузка дают те же
  выходы.
- `teacher`: каждое правило отдельным тестом (разворот, край, тело, хвост, лоб в лоб, рост,
  еда только в пустой клетке).
- `world`: кодировка туда-обратно; обученная сеть на отложенных партиях 32x32 даёт точность
  из п. 6; длинные змейки (100+ клеток) сеть ведёт верно; ничего из `teacher` не
  импортируется в `world` и `game` (проверка по исходникам).
- `player`: вход не выходит за окно; бот не врезается, когда есть безопасный ход; обученный
  соперник выигрывает у случайного и не проигрывает боту сильнее заданного.
- `game`: без экрана (Qt offscreen) - матч проходит от отсчёта до победы, пауза, меню, настройки
  и статистика сохраняются и переживают битый файл, звуки нужной длины, место окна.
- Мутационная проверка: намеренно ломаем правило или градиент - тесты должны упасть.

CI - pytest на Windows, в `.github/workflows/ci.yml` и копия в `.gitea/workflows/ci.yml`
на раннер ПК.
